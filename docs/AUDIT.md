## Находки

### A-001 — двусторонний конфликт файл/каталог после подтверждённой базы

Случайный seed 1000045 и 1000077 выявил потерю версии каталога из видимых деревьев (версия оставалась в истории): если на B прежний каталог заменили файлом, а A-каталог не менялся, правило переноса удалений удаляло его детей. При конфликте типов выбранный каталог должен сохраняться целиком независимо от удаления детей на стороне файла.

Детерминированная регрессия воспроизвела ошибку: 31/32 теста до исправления. Добавлено сохранение всего выбранного поддерева A; после исправления 32/32 PASS. Исходный часовой прогон продолжает тестировать прежнюю сборку для полноценного отчёта, поэтому обнаружения A-001 в нём ожидаемы. Исправленную сборку проверит отдельный проход.

## Продолжение находок

### A-002 — оформление новых окон

Оформление применялось к открытым окнам при активации приложения. Новое окно в уже активном приложении могло получить стандартный шрифт/масштаб/значок. Исправлено: общие DynamicResource для шрифта, размера и значка; статический Loaded-handler с WeakReference для нативного фона, без удержания закрытых окон. Добавлены Windows runtime-проверки.

### A-003 — альтернативные пути Windows

Лексическая проверка не распознавала `C:\folder` и `\\?\C:\folder` как физические алиасы. Добавлено сравнение окончательного пути через handle/ID, проверка предков, отдельная Windows-регрессия. Linux cross-build проходит; runtime-проверка Windows ожидается.

### A-004 — подтверждение направления и штатная двусторонность

Политика подтверждения вынесена из UI-координатора в PlanReviewPolicy. Обратное USB → PC направление сравнивается со своим fingerprint и получает конкретный план. Односторонние изменения B в двустороннем режиме не требуют повторного вопроса, пока нет конфликтов или массовых удалений.

### A-005 — источник операции

Дополнительно ограничен источник каждого payload: он должен принадлежать одному из двух подтверждённых снимков и совпадать с Entry по содержимому. Внешний сконструированный план больше не может копировать данные из произвольного третьего каталога.

### Предстоящие проверки исправлений

- Пропуск вложенных ссылок/исключённых поддеревьев с защитой от удалений.
- Восстановление после сбоя при сменившейся букве/идентичности носителя.
- Ограничения FAT32, повреждённая история, реальные Windows-блокировки.
- Планировщик и настройки: закрытие/GC, ограничение очередей, корректное освобождение ресурсов.

## Границы подтверждения

Файловые runtime-проверки выполняются на Debian Linux x64 / .NET 10; они не подтверждают Windows GUI, драйверы USB, Windows-блокировки, NTFS/FAT/exFAT/SMB, DPI и Narrator. WPF cross-build учитывается отдельно.

### A-006 — ссылки и исключённые поддеревья
Внутренние reparse points пропускаются с отчётом; содержимое их контрагентов защищается от зеркала. Контейнер исключённого ребёнка сохраняется. Case/type-замена затрагивающего его родителя отклоняется до записи. Детерминированные проверки PASS.

### A-007 — recovery и ID накопителя
Журнал различает кандидат и созданный программой временный файл; хранит ID обеих сторон и текущую операцию. Отсутствующий/другой том откладывает cleanup. WindowsStableRoot устраняет перенаправление I/O повторно используемой буквой. Восстановление истории получает отдельный журнал и привязку к текущему корню того же тома. Симуляции PASS; физический USB/Windows runtime ожидаются.

### A-008 — настройки и история
Неизменяемые коллекции, no-op без записи, сохранение корректного .bak при повреждении, ожидание pending saves; импорт выключает автоматику и удаления. История проверяет ID/пути метаданных; повреждённая запись не скрывает весь список. Экспорт конфигурации отделён от архива файлов. Проверки PASS.

### A-009 — лишнее дисковое место при обычном backup
Полное staging на ПК было нужно для двусторонних структурных замен, но также дублировало весь объём односторонней копии. PayloadSources разрешает прямую потоковую передачу при неизменяемом A, сохраняя проверяемый временный B и SHA256. Добавлена проверка отсутствия локальных payload.

### Оптимизации
Индекс имён OneWayMerge, reserved/files индексы TwoWayMerge, счётчик объёма истории на один сериализованный запуск, обновление только изменённых PairViewModel, ограничение промежуточного progress до 10 Гц с первым/последним событием. Проверки файлов и отмены сохранены. before/after/streaming JSON фиксируют конкретные наборы, время и память; условия параллельной нагрузки различались, поэтому единичные отношения не являются контролируемым обещанием ускорения.

### A-010 — новый файл на границе фиксации
Если план ожидал свободный путь, но другой процесс создавал файл между последней проверкой и rename, безусловный overwrite мог его заменить. Исправлено: новая запись использует атомарный move без overwrite; замена разрешена только для Before, существовавшего в плане. То же правило применяется к восстановлению. Добавлены детерминированные граничные регрессии.

### A-011 — временные файлы после прерывания
Зарезервированные GUID-имена временной копии/restore исключаются из сканирования и watcher-сигналов с отображением в плане. Обычные пользовательские .tmp под это правило не попадают. Защищается соответствующее поддерево другой стороны. Добавлена регрессия.

Дополнительно staging ограничен payload изменяемых корней: A продолжает передаваться напрямую даже при необходимости сохранить B-extra во время case-only rename. Проверка смешанного сценария PASS. Защита link-поддеревьев использует индекс предков, а не перебор всех ссылок для каждого файла.

### A-012 — отмена переноса при выключенной истории
Детерминированная проверка воспроизвела потерю единственного B-extra при case-only rename: 55/56 до фикса. Стадированный payload удалялся в finally после отмены, а обычная история была выключена. OperationHistory теперь сохраняет обязательные защитные копии перед разрушительными шагами, чей источник нужен поздним copy-операциям. Они переживают отмену независимо от History; очищаются только после проверки результата и фиксации базы. Проверены восстановление, повтор и заполнение лимита. Это отдельный фикс после frozen optimization snapshot705f600; его нельзя выдавать за тот же бинарный SHA часового профилирования.

### A-013 — case alias и смена типа
57/58 до фикса: ITEM-файл A против item-каталога B мог обойти AllowDeletes=false и оставить дочерние пути под будущим файлом. Тип проверяется до преобразования регистра; при разрешённой замене устаревшие дети удаляются из desired tree. Структурная замена создаёт конфликт, требующий конкретного плана даже при настроенной автоматизации. После фикса 58/58 PASS.
