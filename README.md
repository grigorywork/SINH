# SINH · MSS9LN

Программа синхронизации файлов USB/ПК.

[**Скачать SINH.exe — 0.5.1-preview.1**](https://github.com/grigorywork/SINH/releases/download/v0.5.1-preview.1/SINH.exe) · [ZIP, исходники и SHA256](https://github.com/grigorywork/SINH/releases/tag/v0.5.1-preview.1)

Диагностический выпуск: уточняет причину ошибки доступа к папке; см. раздел «Если появилась ошибка папки».

Самостоятельный синхронизатор папок для Windows 10/11 x64. C# / .NET 10 LTS / WPF / MVVM, компоненты Material Design. Это предварительная версия: Windows Server 2025 CI прошёл (65/65 ядра и WPF); клиентские Windows 10/11, реальные USB/SMB и DPI ещё требуют проверки. Linux-интерфейс — следующий порт после проверки Windows.

## Начало работы

Сначала выполняйте пробные запуски на временных папках.

1. Распакуйте **весь portable-пакет** в папку на флешке или компьютере. Запустите `SINH.exe` обычным пользователем.
2. Нажмите «Добавить пару». Выберите одну или несколько исходных папок (Ctrl/Shift в диалоге Windows); уберите галочки с ненужных. Для нескольких источников внутри назначения создаются отдельные папки с точными исходными именами. Одинаковые имена добавляйте отдельно с разными назначениями. Корень всего диска назначением быть не может.
3. Для первого запуска оставьте «Копирование обновлений A → B» и выключенные удаления. Нажмите «Сравнить» для выбранной строки. Отметьте галочками нужные пары и нажмите «Синхронизировать (N)»: они выполняются по очереди. Снятая галочка ставит пару на паузу и отключает её автоматику. Отмена, отказ от плана или ошибка останавливают общую очередь.
4. Если нужна полная копия с удалениями, выберите «Зеркало A → B» и явно разрешите перенос удалений. При первом запуске, смене настроек и новых массовых удалениях показывается план.
5. Файлы, лежащие **вне B и других настроенных корней**, не участвуют в синхронизации. В режиме обновлений сохраняются и посторонние файлы внутри B. В зеркале содержимое B подчиняется выбранным правилам удалений.

Если изменена копия на USB, односторонний режим предложит выбрать направление. USB → ПК применяется после отдельного плана. Двусторонний обмен использует подтверждённую базу; одновременные изменения сохраняются обеими версиями.

## Автоматический запуск при подключении

Windows не запускает произвольные EXE с флешки автоматически. Один раз на нужном компьютере включите **Настройки → Дополнительно → Автозапуск Windows**. Программа копирует свой EXE в `%LOCALAPPDATA%\SINH\Agent`, запускает его локально и регистрирует HKCU Run без администратора. Затем флешку можно извлекать.

У пары выберите направление **ПК → USB** или **USB → ПК** и включите «При подключении USB» и выполните один успешный ручной запуск. Носитель определяется по GUID тома; изменение буквы не требует менять профиль. Для постоянной работы после закрытия окна выберите «Оставлять в трее». В трее всегда есть «Выход». По умолчанию автозапуск выключен, закрытие завершает приложение. При полностью завершённом SINH вставка флешки не запустит синхронизацию до следующего запуска помощника.

## Сохранность и восстановление

- Сначала сравнение и план; ошибки чтения/отключённый диск не считаются пустой папкой.
- SHA256, временный файл на стороне назначения, проверка и атомарная замена. Данные неизменяемого корня передаются потоком без второй полной копии на ПК. При взаимозависимых структурных изменениях (в том числе двусторонних) изменяемые источники предварительно сохраняются в служебной области; для них нужно дополнительное свободное место на ПК.
- История замен/удалений по умолчанию включена. Хранится **на этом компьютере**, отдельно от USB-копии, в `%LOCALAPPDATA%\SINH\history`. Общий исходный лимит 4096 МиБ; при заполнении замена останавливается. Версии сохраняются до удаления вручную через «История». История на ПК не является ещё одной копией на флешке.
- При выключенной обычной истории всё равно сохраняются защитные версии тех файлов, которые нужны более поздним шагам переноса и могут исчезнуть при отмене. После успешной проверенной фиксации они удаляются; после отмены доступны в «Истории». На них также действует общий лимит области восстановления.
- Отмена сохраняет целостность отдельного целевого файла. Весь набор файлов не является одной транзакцией: уже завершённые операции могут остаться применёнными; база не продвигается при неполном запуске.
- Журнал позволяет убрать записанные временные файлы после сбоя, проверяя ID носителя. Чужой диск на прежней букве не используется для восстановления.
- Служебные имена `.sinh-<32 hex GUID>.tmp` и `.sinh-restore-<32 hex GUID>.tmp` зарезервированы и видны как пропущенные в плане. Незавершённые временные копии не попадают в обмен; обычные пользовательские `.tmp` сохраняются по правилам профиля.
- Вложенные ссылки/junction и исключения пропускаются и видны в плане; их содержимое не обходится и не удаляется зеркалом. Корни-ссылки и неоднозначные имена, различающиеся только регистром внутри одного каталога, отклоняются. Переименование только регистра между сторонами проверяется отдельно.
- Русские/английские/Unicode имена не обрезаются. В тестах есть пути длиннее 500 символов. Ограничения конкретной файловой системы остаются в силе: например FAT32 не хранит файл более 4 ГиБ − 1 байт; слишком длинный отдельный компонент не переименовывается молча.
- Синхронизируются обычные файлы, каталоги и время записи копируемых файлов. ACL, владельцы, NTFS ADS и специальные потоки не переносятся.
- UNC/SMB работает через доступную сессию Windows; программа не запрашивает и не сохраняет сетевые пароли.

Настройки, база, журнал и история: `%LOCALAPPDATA%\SINH`. Родительскую папку профиля выбирать можно: собственная служебная область исключается автоматически. Экспорт/импорт и резервные копии **настроек** находятся в «Дополнительно»; импорт не включает автозапуск, удаления и расписания, создаёт новые ID профилей и ставит пары на паузу. Перед импортом сохраняется предыдущая конфигурация. Частоты копий настроек: вручную, 1/3/10/30 дней.

## Если появилась ошибка папки

В диагностическом preview 0.5.1 ошибка различает отсутствие папки, отказ доступа, путь к файлу и сбой ввода-вывода; рядом указан код ОС. Нажмите «Копировать ошибку», чтобы получить подробности: версию, этап, настроенные и фактически найденные пути, стек ошибки и повторную проверку атрибутов корней. Локальные отчёты — `%LOCALAPPDATA%\SINH\errors`, не больше 100, срок по настройке журнала. Содержимое файлов не записывается, отчёты автоматически никуда не отправляются.

Удаление последнего файла в двусторонней паре проверяется в обе стороны: корни сохраняются, повторная синхронизация работает. Сообщённый случай, когда папка открывается в Проводнике, но недоступна SINH, пока не воспроизведён на компьютере пользователя; диагностический preview не объявляет его причину исправленной.

## Сборка и проверки

SDK закреплён в `global.json`: **10.0.404**. MaterialDesignThemes **5.4.0**, `packages.lock.json`. На компьютере с SDK:

```powershell
dotnet restore SINH.sln --locked-mode
dotnet build SINH.sln -c Release --nologo -warnaserror -m:1
dotnet run --project tests/Sinh.Checks -c Release --no-build
```

На Windows: `scripts/Check-Windows.ps1` — отдельные проверки ядра, WPF runtime и PNG-снимки окон. Это не заменяет проверки на настоящих Windows 10/11 с USB/SMB, сенсором, Narrator и DPI. Список: [docs/WINDOWS-VALIDATION.md](docs/WINDOWS-VALIDATION.md).

```powershell
dotnet publish src/Sinh.App/Sinh.App.csproj -c Release -r win-x64 --self-contained true -o artifacts/publish
```

Длительная проверка: `dotnet run --project tests/Sinh.Checks -c Release -- --soak 3600 1000000 artifacts/soak.json 73000` — не менее часа и 73 000 сценариев. Бенчмарк: `--benchmark artifacts/performance.json`. Все проверки используют временные каталоги, а не пользовательские пары.

Результаты и незакрытые ограничения — [docs/NEXT-CHAT.md](docs/NEXT-CHAT.md), [docs/AUDIT.md](docs/AUDIT.md), `docs/validation/`. Linux cross-build не подтверждает работу WPF на Windows.

## Подпись, ресурсы и оформление

Издатель в интерфейсе: **MSS9LN**. Каждое второе нажатие на подпись подпрыгивает, девятое открывает пасхалку. Анимации учитывают системное отключение анимаций Windows.

Основной значок — голубые зеркальные элементы. Старые варианты и их выбор удалены. Значок окна и трея использует тот же ресурс без переписывания подписанного EXE. Закреплённые значки обновляются по правилам кеша Windows; Explorer не перезапускается.

Предварительная цифровая подпись, если приложена, **самоподписанная MSS9LN**, не является сертификатом доверенного издателя и может вызывать предупреждения Windows. Сертификат не устанавливается в доверенные автоматически. Для подписи предоставленным доверенным сертификатом: `scripts/Sign-Windows.ps1`. Сведения конкретного артефакта и SHA256 указываются рядом с пакетом.

Шрифты и их лицензии встроены в EXE; копии лицензий приложены. Источники: [docs/ASSETS.md](docs/ASSETS.md). Material Design Toolkit — независимый MIT-проект, а не приложение Google.
