## Новое задание выполнено

- Сохраняемые переключатели «Вид: компактный / подробный» и «Группы». CompactPairs/GroupPairs — глобальные параметры, не свойства файлового плана. Новые значения по умолчанию true; старый JSON загружается без миграции путей/ID.
- Пары с общим родителем назначения показываются одной раскрываемой строкой (например, шесть источников из разных мест → отдельные копии внутри F:\Копии). Группы изначально свёрнуты. Заголовок показывает выбранные/все, активность и ошибки. Сворачивание не выключает пары, сбрасывает скрытое выделение. Галочки по-прежнему сохраняют паузу; очередь работает с исходным плоским списком и прежним порядком.
- Компактные строки показывают имя, короткий режим, пути в одну строку, статус и последний результат. Полные пути — tooltip/подробный вид; данные не обрезаются. Области нажатия минимум40 сохранены. Заголовки длинных путей обрезаются только визуально, Ink для light/dark проверен.
- «Удалить из списка» на главной: подтверждение с названием/путями, только удаление настройки пары; исходники/копии/история физически не удаляются. Действие блокируется при Busy/Batch/Dialog, доступно также в настройках через общий сервис.
- Новый редактор накапливает папки при повторном «Добавить папки…», включая разные места; снятые галочки сохраняются. Для нескольких источников остаются независимые подпапки назначения; совпадающие имена отклоняются.
- Рефакторинг: чистые FolderGrouping/ProfileList, PairListPresentation/FolderGroup, MainViewModel.List partial, общие FolderPairRemoval и PairListTemplates.xaml, отдельный FolderSources.

## Известная прежняя проблема

Пользователь удалил ОДИН файл; SINH0.5 сообщил «Папка недоступна» для F:\изображения\Wallpapers, хотя папка открывалась в Проводнике. На скриншоте двусторонняя пара F:\изображения\Wallpapers ↔ F:\обои. Причина до сих пор НЕ воспроизведена и НЕ считается исправленной. Пользователь обещал проверить диагностический EXE, текста ошибки пока не прислал.
Сохранены RootAccessException (точная причина/код Windows), местные JSON в %LOCALAPPDATA%/SINH/errors и «Копировать ошибку». Не трактовать недоступный корень как пустой и не создавать автоматически. При повторе требуется скопированный текст с версии/этапом/configured-resolved путями/стеком/повторным probe. Данные файлов не пишутся в отчёт и автоматически не отправляются.

## Следующий шаг / эксплуатация

Перед новым EXE завершить старый SINH через «Выход» в трее. Если помощник автозапуска уже включён, в новом EXE выключить и снова включить «Автозапуск Windows», чтобы обновилась локальная копия. Обычный запуск другого EXE не заменяет уже работающий процесс.
Реальные Windows10/11, физические USB/SMB, стандартный пользователь, DPI100/125/150/200/несколько мониторов, сенсор/Narrator остаются непроверенными. Server CI их не заменяет. Linux GUI — позже. Первые файловые проверки только на временных папках. Старые часовые отчёты относятся к своим SHA, не автоматически к новому EXE.
Пользователь просит минимум текста, автономность и рефакторинг. Для скачивания давать публичный GitHub EXE URL, не /workspace. Сохраняются Material Design/WPF/.NET10, один голубой зеркальный значок, MSS9LN (bounce2/egg9), безопасные режимы/история/планы и независимые пары.
