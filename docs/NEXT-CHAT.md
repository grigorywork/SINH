# SINH — передача работы

Версия исходника: 0.3.0, main, `/workspace/sinh`. Стек: C# / SDK 10.0.404 / .NET 10 LTS / WPF-MVVM / MaterialDesignInXamlToolkit 5.4.0. Рабочее имя окончательно **SINH**.

## Обязательная цель

Завершить отдельный Windows-синхронизатор (10/11 x64), затем аудит/исправления/оптимизацию по часу, в конце анимации, portable-пакет, цифровую подпись и GitHub. Linux GUI — позднее. Не задавать вопросов: владелец явно разрешил автономную работу. Последнее уточнение: не забывать содержательный рефакторинг по модулям (скрин Rust Shell — пример структуры, не смена стека).

Важны длинные русские/английские/Unicode имена, отсутствие изменений посторонних файлов на USB, подтверждение USB → PC, подпись MSS9LN (каждое второе нажатие подпрыгивает, девятое открывает пасхалку). Фирменный эскиз зеркального голубого значка лежит в design/; три NoteLS-значка сохранены.

## Что уже есть

- App / Core / Settings / Checks / WindowsChecks. Внутри App Views, ViewModels, Services, Controls, Platform/Windows; карта в ARCHITECTURE.md.
- Discovery → Merge strategies (OneWayMerge, TwoWayMerge) → OperationPlanner → SyncExecutor. SyncPlanner — фасад; PlanReviewPolicy отделена от UI.
- Три режима, подтверждённая база, сохранение обеих конфликтных версий/поддеревьев, удаления по правилам, план без записи, контроль корней и Windows-физических алиасов, SHA256, потоковые копии/проверка/атомарная замена, отмена и журнал.
- История замен/удалений с лимитом и восстановлением. Служебная область на ПК вне копий; исходные и посторонние USB-файлы защищены границами пары. B не может быть корнем диска.
- Код Windows USB-ID/смены буквы/контроля ID перед commit, наблюдение/debounce/контрольные сканы, интервалы, очередь одна пара, пауза, трей/Exit/уведомления, один процесс, HKCU Run и локальная установка помощника (выкл по умолчанию).

## Следующие исправления

1. Корректно пропускать вложенные ссылки/исключённые поддеревья и защищать их от mirror-удалений; сейчас nested links прерывают scan, а исключённый ребёнок мешает удалить родителя.
2. Проверить recovery при другом диске на прежней букве: журнал должен учитывать ID носителя, нельзя чистить чужой временный файл. При недоступном диске recovery не должен блокировать запуск приложения.
3. Уточнить FAT32/component limits, повреждённую историю, отмену/изменение источника во время копирования; Windows file locks — отдельная CI-проверка.
4. SettingsStore: заморозить коллекции, не терять корректный .bak при повреждении, не писать одинаковые значения, ожидать pending saves при закрытии настроек; экспорт/импорт и бэкап конфигурации отдельно от истории.
5. Разрешить выбранную папку-профиль, исключая собственную служебную область, а не копируя её в себя. Физические алиасы Windows должны учитываться в границах.
6. Оптимизировать квадратичные обходы OneWayMerge/TwoWayMerge и пересчёт размера всей истории для каждого архива. Сохранить обязательные проверки SHA256 и целостность файлов.
7. Довести RU/EN статусы/меню и Win runtime tests, сделать снимки настоящего WPF UI через Windows CI. Не объявлять Windows Server runner проверкой Windows 10/11 клиента.
8. Последними добавить умеренные анимации с учётом отключённых Windows-анимаций.
