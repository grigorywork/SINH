# Текущий этап — компактные группы 0.6.0-preview.1

По заданию владельца: переключение компактный/подробный вид, раскрывающиеся группы по общей папке назначения (шесть разных источников в общей папке USB), удаление пар из главного окна без удаления файлов. Параметры вида сохраняются отдельно от профилей; группировка только отображение, движок и очередь продолжают работать с плоскими независимыми парами. Выбор папок в новом редакторе накапливается при повторном открытии диалога, позволяя выбрать разные места.

Рефакторинг: FolderGrouping / ProfileList — чистые операции настроек; PairListPresentation / FolderGroup — отдельный слой отображения; MainViewModel.List partial; общие FolderPairRemoval и XAML-шаблоны списка. Компактные строки сохраняют min40 области нажатия, пути полностью доступны в tooltip/подробном виде. Группы изначально свёрнуты, заголовок показывает выбранные/все, ошибки/активность; сворачивание сбрасывает скрытое выделение. Удаление подтверждается с названием/путями; заблокировано во время синхронизации/очереди, меняет только конфигурацию.

Проверки этапа ещё выполняются: Linux cross-build был успешен до последних тестов; требуется финальный build/core и Windows WPF с шестью папками, измерением высоты/заголовка, collapse/selection, ошибками/галочками, очередью, удалением и сохранением предпочтений. Не объявлять проверенным Windows UI до CI.
Следующий шаг: финальные проверки → Git → Windows CI/исправления → пакет/подпись/smoke → публичный EXE.

ВАЖНО: прежняя пользовательская ошибка F:\изображения\Wallpapers после удаления ОДНОГО файла при доступной папке в Проводнике остаётся невоспроизведённой. Новая функциональность не означает исправления этой причины; сохранить диагностику 0.5.1 и ждать «Копировать ошибку». Предыдущая передача ниже.

## Активная проблема

Пользователь удалил ОДИН файл. SINH показал «Папка недоступна» для `F:\изображения\Wallpapers`. Папка после этого открывается в Проводнике (подтверждено пользователем). Скриншот: двусторонняя пара `F:\изображения\Wallpapers ↔ F:\Обои`; обе стороны на F:. Первая независимая пара C: → F:\Загрузки завершилась успешно.
Причина реального сбоя пока **НЕ воспроизведена и НЕ считается исправленной**. Не объявлять проблемой удаления корневой папки: пользователь это явно опроверг.

## Код и изменения

Код: a691eafedfd3fbc39a7709cf51cabf9c3abc551e. Source archive / release tag: cb28a176332db0f131265c1b5f11c992ebc1e659. Далее main меняет только документы и ссылки.

- RootAccessException различает missing / access denied / not directory / I/O с нативным кодом и inner exception. File.GetAttributes заменяет подавляющий ошибки Directory.Exists в PathRules.Root. Ошибка корня никогда не становится пустым снимком; автоматического создания недоступных корней нет.
- SyncFailureReport — отдельный модуль локальной диагностики: версия, OS, этап, configured/resolved пути и IDs, стек ошибки, повторная проверка атрибутов корней. `%LOCALAPPDATA%/SINH/errors`, не больше100 отчётов, срок по LogDays. Содержимое файлов не записывается, автоматической отправки нет. Ошибка записи отчёта сохраняет исходную ошибку в памяти.
- «Копировать ошибку» видно только при ошибке; success очищает старое состояние. Общий код ошибок вынесен из файлового движка/координатора; синхронизация/политика удаления не ослаблены.
- Возможности 0.5.0 сохранены: множественный выбор, галочки/пауза, последовательная очередь, независимые настройки, USB → ПК, только зеркальный голубой значок, пять кратких разделов настроек, MSS9LN (2-е нажатие bounce, 9-е easter egg), .NET10/WPF/Material, identity SINH.FolderSync.Desktop.

## Следующий шаг

Пользователь завершает старый SINH через «Выход» в трее, запускает новый EXE, повторяет синхронизацию. Если ошибка повторится — нажимает «Копировать ошибку» и присылает текст. Требуется реальный native code / configured-resolved roots / post-failure probe, чтобы устранить причину. До получения данных не приписывать сбой конфликтам или удалению самой папки.
Если включён помощник автозапуска, для обновления его EXE в новой portable-версии выключить и снова включить «Автозапуск Windows»; один запуск скачанного EXE не заменяет уже работающий процесс автоматически.
Реальные Windows10/11, физические USB/SMB, DPI/сенсор/Narrator/неадмин остаются непроверенными; Server CI не подменяет их. Linux GUI отложен. Предыдущие часовые отчёты относятся к своим SHA, не автоматически к новому EXE. Пользователь просит минимум текста/автономность/рефакторинг. Для скачивания использовать публичный GitHub EXE URL, не локальный /workspace.
